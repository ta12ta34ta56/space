## Bug found because of your keys

Supabase issued you the **new** key format (`sb_publishable_…` / `sb_secret_…`).
My validator only accepted the old JWT style, so the server would have refused
to start. Fixed, and hardened while I was there — it now rejects:

- the publishable key in the secret slot (silently disables all security)
- the secret key in the anon slot (would ship your secret to browsers)
- both slots holding the same value
- a URL ending in `/rest/v1` — **which is what you sent me**
- `http://` instead of `https://`
- a Stripe `pk_` key in the secret slot, or a malformed `whsec_`

9 checks, all passing. Each of these is a real mistake people make, and each
one now stops the deploy instead of causing a silent breach.
